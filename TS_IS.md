**ТЕХНИЧЕСКОЕ ЗАДАНИЕ · MVP**

**Информационная система супермаркета**

# 1. Общие сведения

Наименование: «Информационная система супермаркета» (ИС). Тип системы: учебное настольное приложение для одного небольшого магазина.

# 2. Назначение и цель

Цель - создать простую программу для хранения списка товаров, учёта количества товаров на складе, регистрации продаж и просмотра основных итогов.

- Хранить единый каталог товаров.
- Показывать актуальные остатки.
- Регистрировать продажи и автоматически уменьшать остатки.
- Позволять просматривать историю продаж и простую сводку.

# 3. Границы MVP

В первую версию входят только функции, необходимые для демонстрации основного процесса магазина: товар → поступление → продажа → обновлённый остаток → отчёт.

Не входят в MVP: программы лояльности и бонусные карты, акции, возвраты, комбинированная оплата, онлайн-оплата, работа кассы без сети, интеграция с 1С/SAP, ЕГАИС, «Честный Знак», банковским эквайрингом, ТСД и весами, доставка, несколько магазинов, ABC/XYZ-анализ и автоматический заказ поставщику.

# 4. Пользователи и права

- Администратор: полный доступ; добавление и изменение пользователей, товаров и категорий.
- Товаровед: добавление и изменение товаров, регистрация поступлений, просмотр остатков.
- Кассир: просмотр каталога и оформление продаж; не может менять каталог и складские поступления.

Для учебной демонстрации допускаются заранее созданные тестовые учётные записи. Пароли должны храниться в виде хеша, а не открытым текстом.

# 5. Функциональные требования MVP

**Вход -** Пользователь вводит логин и пароль. После входа доступны только разрешённые его роли разделы.

**Каталог товаров -** Система показывает список товаров и позволяет искать товар по названию или артикулу.

**Карточка товара -** Для товара хранятся артикул (уникальный), название, категория, цена и единица измерения.

**Категории -** Администратор может создавать и изменять категории товаров.

**Поступление -** Товаровед выбирает товар и указывает положительное количество поступления. Система увеличивает остаток.

**Продажа -** Кассир выбирает товар, указывает количество и добавляет его в чек. Система рассчитывает сумму.

**Проверка остатка -** Система не позволяет продать больше товара, чем есть на складе.

**Сохранение продажи -** После подтверждения продажа сохраняется в базе, а остаток товара уменьшается.

**История продаж -** Пользователь с соответствующим правом может просмотреть список продаж: дата, номер, кассир и сумма.

**Сводка -** Система показывает количество продаж и общую выручку за выбранный день или период.

# 6. Основные сценарии работы

## 6.1. Добавление товара

1. Администратор открывает раздел «Товары».
2. Нажимает «Добавить».
3. Вводит артикул, название, категорию, цену и единицу измерения.
4. Система проверяет заполнение полей и уникальность артикула.
5. При успешной проверке товар появляется в каталоге.

## 6.2. Поступление товара

6. Товаровед выбирает товар.
7. Вводит количество поступивших единиц.
8. Система проверяет, что количество больше нуля.
9. После подтверждения остаток увеличивается на указанное количество.

## 6.3. Продажа товара

10. Кассир находит товар и указывает количество.
11. Система проверяет наличие нужного количества на складе.
12. Товар добавляется в чек; сумма рассчитывается как цена × количество.
13. Кассир подтверждает продажу.
14. Система сохраняет продажу и уменьшает остаток.

## 6.4. Просмотр отчёта

15. Пользователь открывает раздел «Отчёты».
16. Выбирает дату или период.
17. Система показывает количество продаж и сумму выручки за период.

# 7. Нефункциональные требования

- Интерфейс и сообщения - на русском языке.
- Приложение рассчитано на работу на одном компьютере в рамках демонстрации MVP.
- При обычном поиске по локальной базе до 5 000 товаров результат должен отображаться не более чем за 1 секунду на тестовом компьютере команды.
- После подтверждения продажи данные должны сохраняться в MySQL; при перезапуске история и остатки не теряются.
- Нельзя сохранить товар с пустым названием, отрицательной ценой или повторяющимся артикулом.
- Продажа и изменение остатков выполняются как одна транзакция БД: если сохранение продажи не удалось, остаток не должен измениться.
- Перед удалением товара система показывает подтверждение. Товары, участвовавшие в продажах, предпочтительно деактивировать, а не удалять.

# 8. Технологии и архитектура

- Java 21 - основная логика приложения.
- JavaFX - графический интерфейс настольной программы.
- MySQL 8 - хранение пользователей, товаров, остатков и продаж.
- Python 3 - вспомогательные скрипты для подготовки тестовых данных, проверки/анализа выгрузок и демонстрационных отчётов; Python не является обязательным сервером приложения.
- Git и GitHub - совместная работа; JUnit 5 - тестирование Java-кода.

Для MVP используется простая архитектура: JavaFX-интерфейс → классы бизнес-логики → слой работы с MySQL. Python-скрипты запускаются отдельно и не участвуют в каждой операции кассира.

# 8. Журнал аудита

- Успешный и неудачный вход.
- Выход из системы.
- Блокировка и разблокировка аккаунта.
- Создание и изменение товаров.
- Регистрация поступлений.
- Оформление продаж.
- Изменение ролей пользователей.
- Попытки выполнить запрещённые действия.

Записи содержат дату, время, пользователя, тип события, объект и результат операции. Пароли и другие секреты не записываются.

# 10. Основные таблицы базы данных

- users: id, login, password_hash, role, is_active.
- categories: id, name.
- products: id, sku, name, category_id, price, unit, is_active.
- stock: product_id, quantity, updated_at.
- sales: id, cashier_id, created_at, total.
- sale_items: id, sale_id, product_id, quantity, unit_price, line_total.

В MVP поставщики и партии товара не ведутся отдельно. Движение остатков ограничено поступлением и продажей.

# 11. Проверка и приёмка

- Успешный вход под каждой тестовой ролью; проверка ограничений доступа.
- Создание товара и отказ при повторном артикуле или некорректной цене.
- Поступление 20 единиц увеличивает остаток с 0 до 20.
- Продажа 3 единиц уменьшает остаток с 20 до 17.
- Попытка продать 18 единиц при остатке 17 отклоняется.
- Продажа сохраняется в истории с корректной суммой.
- Отчёт за выбранный период показывает правильное количество продаж и выручку.
- После перезапуска приложения товары, остатки и история остаются в базе.
